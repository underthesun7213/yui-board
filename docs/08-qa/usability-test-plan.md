## 1. 목적

기능 QA 는 "만든 대로 동작하는가"를 봤다. 사용성 테스트는 "입주자가 실제로 쓸 수 있는가, 그리고 믿는가"를 본다.

| # | 알고 싶은 것 | 관련 |
|---|---|---|
| UG-1 | 처음 쓰는 입주자가 네 탭(홈·캘린더·일본어·지도)의 역할을 설명 없이 이해하는가 | PRD G1 |
| UG-2 | 번역 표시와 "원문 보기"를 알아차리고, 번역된 글을 믿고 읽는가 | B-7, PRD G2 |
| UG-3 | **익명이라는 것을 믿는가.** 무엇이 상대에게 보이고 무엇이 안 보이는지 정확히 이해하는가 | B-4, PRD G3 |
| UG-4 | 프로필 교환 경고(내 이름과 위치가 거절당해도 전달됨)를 읽고 이해한 뒤 결정하는가 | X-2, PRD G5 |
| UG-5 | 신고 흐름이 부담 없이 끝나는가. 신고 후 피드로 이동하는 것(IA-3)이 혼란을 주는가 | M-1, IA-3 |
| UG-6 | 하위 화면에서 뒤로 갈 때 기대와 실제(IA-1: 항상 피드로 감)가 어긋나는가 | IA-1, IA-2 |
| UG-7 | 일본어 분기형 에피소드가 재미있고, 피드백이 학습에 도움이 되는가 (일본어 비원어민) | J-2, J-3 |
| UG-8 | 지도에서 원하는 장소를 찾고 Google 지도로 넘어갈 수 있는가 | P-2, P-3 |

## 2. 참가자

### 2.1 구성 (5~8명)

| 그룹 | 인원 | 조건 | 진행 언어 |
|---|---|---|---|
| A. 일본인 입주자 | 2~3명 | 結 -YUI- 장기 거주, 일본어 모국어 | 일본어 UI |
| B. 교환학생 (영어권 또는 영어 사용) | 2~3명 | 입주 1학기 이내, 일본어 초급~중급 | 영어 UI |
| C. 교환학생 (한국어 모국어) | 1~2명 | 입주 1학기 이내 | 한국어 UI |
| (선택) D. RA | 1명 | RA 경험자 | 본인 선호 언어. 신고 큐(HOME-05) 과제만 추가 |

- 최소 5명이면 주요 문제 대부분이 드러난다는 관례를 따르되, 언어 3개 × 거주 형태 차이가 크므로 6~8명을 목표로 한다.
- 성별, 학년, 층이 한쪽으로 몰리지 않게 한다. 같은 유닛 사람끼리는 같은 날 하지 않는다 (서로의 과제 내용을 듣지 않도록).
- **제외:** 이 프로젝트에 참여한 사람, 앱을 미리 본 사람.

### 2.2 모집

- 기숙사 공지판, RA 를 통한 안내. 모집 문구에 "앱을 시험하는 것이지 당신을 시험하는 것이 아니다"를 넣는다.
- 사례: 학내 규정에 맞는 소액 상품권 또는 음료. 금액은 사무실과 협의.
- 선별 질문: 거주 기간, 모국어, 일본어 수준(자기 평가), 평소 기숙사 정보를 얻는 경로(Instagram, 게시판 등).

## 3. 방법

| 항목 | 내용 |
|---|---|
| 형식 | 1:1 대면, 생각 말하기(think-aloud), 진행자 1명 + 기록자 1명 |
| 장소 | 기숙사 라운지 또는 스터디룸 (조용한 곳) |
| 시간 | 1인 40분 (도입 5, 과제 25, 사후 질문 10) |
| 기기 | 가능하면 참가자 본인 휴대폰. 안 되면 준비한 iPhone / Android 1대씩. 홈 화면 설치 상태로 시작 |
| 버전 | 같은 커밋으로 고정. 세션 사이에 고치지 않는다 |
| 상태 초기화 | 세션마다 앱을 새로 연다 (mock data 라 새로고침하면 초기화) |
| 기록 | 화면 녹화(동의 시), 기록자 메모, 과제별 시간·성공 여부·SEQ |

> 프로토타입은 mock data 로 동작하고, 글은 새로고침하면 사라진다. 시작 전에 참가자에게 이 사실을 알리고, "실제 다른 입주자에게 보이지 않는다"는 점을 분명히 한다.

## 4. 과제

각 과제는 IA 의 유저 플로우에 대응한다. 과제 문장은 정답 버튼 이름을 쓰지 않는다. 진행 언어로 번역해 카드로 보여 준다.

| 과제 | 플로우 | 시나리오 (참가자에게 주는 문장) | 성공 기준 | 제한 시간 |
|---|---|---|---|---|
| T1 | F-1 | "3층 키친에 있는 프라이팬에 관한 글을 찾아서, 원래 어떤 언어로 쓰였는지 확인하고, 마음에 들면 공감을 눌러 주세요." | 해당 글 상세 진입 + 원문 언어 확인(원문 보기 사용 또는 언어 표시 언급) + 좋아요 | 3분 |
| T2 | F-2 | "이번 주말에 밥솥을 팔고 싶어요. 판매 글을 올려 보세요." | 양도 게시판으로 글 등록 완료 (게시판을 나중에 바꿔서 입력이 사라지는 경우를 기록 — QA BUG-03) | 4분 |
| T3 | F-3 | "어떤 글에 다른 입주자를 특정할 수 있는 내용이 있다고 해 봅시다. 운영자에게 알려 주세요." (대상 글 지정) | 사유 "특정 가능" 선택해 신고 완료 | 3분 |
| T4 | F-4 | "중고 밥솥 글을 쓴 사람과 연락하고 싶어요. 연락할 방법을 찾아 보세요. 단, 실제로 보낼지는 직접 판단하세요." | 교환 요청 시트까지 도달. **보낼지 말지는 성공 여부와 무관.** 사후에 경고 내용을 설명할 수 있으면 이해 성공 | 4분 |
| T5 | F-4 | "누군가 당신에게 프로필 교환을 요청했어요. 확인하고 수락해 보세요." | HOME-06 진입 + 수락 | 2분 |
| T6 | F-5 | "9월 12일 토요일에 있는 교토 당일치기에 참가 신청하고, 휴대폰 캘린더에도 넣어 보세요." | 참가 표시 + .ics 저장(또는 캘린더 앱 열림) | 4분 |
| T7 | F-5 → 뒤로 | "방금 본 행사 말고, 같은 달의 다른 행사를 하나 더 보세요." | 캘린더로 돌아가 다른 이벤트 상세 진입 (뒤로가 피드로 가는 문제 관찰 — IA-1) | 2분 |
| T8 | F-6 | (일본어 비원어민) "일본어 탭에서 친구와 오사카에 놀러 가는 에피소드를 끝까지 해 보세요." / (일본어 원어민) "에피소드 하나를 보고, 교환학생 친구에게 추천할지 말해 주세요." | 엔딩 카드 도달 / 의견 제시 | 6분 |
| T9 | F-7 | "結에서 걸어갈 수 있는 병원을 찾아서 Google 지도로 열어 보세요." | 의료 카테고리 → 장소 카드 → Google 지도 링크 | 3분 |
| T10 | SYS-01 | "앱을 당신이 가장 편한 언어로 바꿔 보세요." (기본 영어 상태에서 시작한 참가자만) | 언어 전환 완료 (지도 탭에서 바꾸면 지도가 사라지는 문제 관찰 — QA BUG-01) | 1분 |
| (RA) T11 | F-3 | "신고가 들어왔어요. 확인하고, 문제가 있으면 처리해 주세요." | 신고 큐 진입 + 유지/숨기기 판단. 댓글 숨김이 실제로 안 되는 것(QA BUG-02)을 알아차리는지 관찰 | 4분 |

과제 순서: T10(해당자) → T1 → T2 → T3 → T4 → T5 → T6 → T7 → T9 → T8. T8 은 길고 성격이 달라 마지막에 둔다.

## 5. 측정 지표

| 지표 | 정의 | 수집 방법 |
|---|---|---|
| 과제 성공률 | 성공 / 부분 성공 / 실패 (도움 요청, 제한 시간 초과, 포기는 실패) | 기록자 판정, 성공 기준표 |
| 과제 시간 | 과제 카드 읽기 끝 → 성공 기준 충족 시점 (초) | 녹화 타임스탬프 |
| SEQ | 과제 직후 "이 과제는 얼마나 쉬웠나요?" 7점 척도 (1 매우 어려움 ~ 7 매우 쉬움) | 진행 언어로 된 카드 |
| 오류 수 | 목표와 무관한 화면 진입, 되돌리기 | 녹화 |
| 이해도 (UG-3, UG-4) | 사후 질문에서 익명성·교환 경고를 정확히 설명했는가 (정확 / 부분 / 오해) | 사후 인터뷰 |
| 신뢰 | "이 앱에 실명으로 말하기 어려운 이야기를 쓸 수 있겠는가" 5점 척도 + 이유 | 사후 질문 |
| 관찰 이슈 | 이슈별 발생 참가자 수와 심각도(치명/높음/중간/낮음) | 세션 후 기록자·진행자 합의 |

목표치(참고용, 판정 기준 아님): 과제별 성공률 80% 이상, SEQ 평균 5.5 이상. T4 는 성공률보다 **이해도**를 우선한다.

## 6. 진행 스크립트

진행 언어(일본어 / 영어 / 한국어)로 미리 번역해 둔다. 아래는 한국어 원본이다.

### 6.1 도입 (5분)

> 와 주셔서 감사합니다. 저는 ○○이고, 옆에 계신 분은 메모를 맡은 ○○입니다.
>
> 오늘은 기숙사 입주자용 앱의 시제품을 써 보시면서 어디가 쉽고 어디가 어려운지 알아보려고 합니다. **앱을 시험하는 것이지 당신을 시험하는 것이 아닙니다.** 막히는 곳이 있다면 그건 앱의 문제이고, 그걸 찾는 게 오늘의 목적입니다.
>
> 하시는 동안 생각나는 것을 소리 내서 말씀해 주세요. "이건 뭐지?", "여기 누르면 될 것 같은데" 같은 것도 좋습니다.
>
> 이 앱은 시제품이라 가짜 데이터로 움직입니다. 여기서 쓰는 글이나 요청은 **다른 입주자에게 전달되지 않고**, 새로고침하면 사라집니다. 화면에 나오는 이름과 방 번호도 모두 가짜입니다.
>
> 질문이 있으시면 하셔도 되지만, 과제 중에는 제가 바로 답하지 않을 수 있습니다. 끝나고 다 답해 드리겠습니다. 언제든 그만두셔도 됩니다.
>
> (동의서 확인 — §7) 시작해도 될까요?

### 6.2 사전 질문 (2분, 도입에 포함)

1. 기숙사에서 행사나 생활 정보를 주로 어디서 얻으세요?
2. 다른 입주자에게 하고 싶은 말이 있었는데 못 한 적이 있나요? (예시만, 자세한 내용은 묻지 않음)

### 6.3 과제 (25분)

- 과제 카드를 건네고 읽게 한다. "다 읽으셨으면 시작해 주세요."
- 막혀서 30초 이상 말이 없으면: "지금 무엇을 찾고 계세요?" (힌트 아님)
- 2분 이상 진전이 없거나 참가자가 포기 의사를 밝히면: 실패로 기록하고 "괜찮습니다, 다음으로 넘어가죠."
- 과제마다 끝나면 SEQ 카드.
- **유도 금지:** "여기를 눌러 보세요", "번역 버튼 보이세요?" 같은 말을 하지 않는다.

### 6.4 사후 질문 (10분)

1. 방금 쓴 앱을 친구에게 한 문장으로 설명한다면?
2. (UG-3) 홈에 글을 쓰면 다른 사람에게 무엇이 보인다고 생각하세요? 운영자에게는요?
3. (UG-4) 연락처 교환을 요청할 때 상대에게 무엇이 전달된다고 했나요? 상대가 거절하면요?
4. (UG-2) 다른 언어로 쓰인 글을 읽을 때 번역을 믿을 수 있었나요? 원문을 볼 수 있다는 것을 알았나요?
5. 이 앱에 실명으로는 하기 어려운 이야기를 쓸 수 있을 것 같나요? (5점) 왜 그렇게 생각하세요?
6. 가장 헷갈렸던 곳 하나, 가장 좋았던 곳 하나.
7. (교환학생) 입주 첫 주에 이 앱이 있었다면 무엇이 달랐을까요?

### 6.5 마무리

> 감사합니다. 오늘 말씀해 주신 내용은 이름 없이 정리합니다. 녹화 파일은 분석이 끝나면 지웁니다. 궁금한 점 있으세요?

사례 전달, 영수 확인(이름이 필요한 경우 동의서와 분리 보관).

## 7. 동의 · 익명성

이 앱의 핵심이 익명성이므로, 테스트 자체도 같은 원칙을 지킨다.

| 항목 | 방침 |
|---|---|
| 동의서 | 3개 언어로 준비. 목적, 녹화 여부, 보관 기간, 철회 방법, 사례 내용. 서명 전 구두로도 설명 |
| 녹화 | **화면과 음성만**, 얼굴은 찍지 않는다. 녹화를 거부해도 참가 가능 (메모만) |
| 식별자 | 참가자는 P1, P2 … 로만 기록. 이름·방 번호·Instagram 등은 메모·녹화 파일명·결과 문서에 남기지 않는다 |
| 대응표 | 참가자 번호 ↔ 이름 대응표가 필요하면(사례 지급 등) 결과와 분리해 진행자 1명만 보관, 사례 지급 후 삭제 |
| 개인 이야기 | 사전·사후 질문에서 다른 입주자를 특정할 수 있는 이야기가 나오면 기록하지 않거나 즉시 일반화한다 ("같은 층 사람과의 갈등" 수준) |
| 본인 휴대폰 | 참가자 기기를 쓸 경우 화면 녹화는 앱 화면만. 알림이 녹화되지 않게 방해 금지 모드를 요청 |
| 보관 | 녹화 파일은 분석 완료 후(최대 30일) 삭제. 결과 문서에는 인용만, 원본 미첨부 |
| 법령 | 일본 개인정보보호법(APPI)과 대학의 연구·조사 관련 규정 확인. 필요하면 대학 윤리 절차를 먼저 밟는다 |
| 철회 | 세션 중·후 언제든 철회 가능. 철회 시 해당 참가자 메모와 녹화 삭제 |
| 운영자·RA 와의 관계 | RA 참가자에게도 다른 참가자의 정체를 알리지 않는다. 결과를 기숙사 사무실에 공유할 때 개인을 추정할 수 있는 조합(국적+층+학년 등)을 쓰지 않는다 |
