## 1. 목적

1. PRD 의 P0·P1 요구사항 중 **프로토타입에 들어 있는 것**이 의도대로 동작하는지 확인한다.
2. 프로토타입에 없는 요구사항(백엔드, 미구현 기능)은 테스트 케이스만 먼저 정의해, M1 이후 바로 실행할 수 있게 한다.
3. 이 제품의 핵심 신뢰 장치인 **익명성·개인정보(PRD §7)** 를 별도 케이스로 관리한다.

### 3.2 언어

모든 화면 케이스는 **en / ja / ko 세 언어**로 실행한다. 별도 표시가 없으면 "3개 언어 모두 기대결과 충족"이 Pass 조건이다.
레이아웃 케이스는 한국어(가장 긴 언어)를 기준으로 판정하되, 일본어 CJK 줄바꿈도 함께 본다.

### 3.3 화면 폭

360 / 375 / 390 / 414 / 430px. 기준 폭은 375px.

### 3.4 서빙

- `python3 -m http.server` 로 저장소 루트를 서빙 (`localhost` 라 서비스 워커 동작)
- 배포 확인은 GitHub Pages 하위 경로(`/<repo>/`)에서 별도로 한다.
- 외부 의존: Leaflet / markercluster (cdnjs), 지도 타일 (tile.openstreetmap.org). 네트워크가 막힌 환경에서는 지도 관련 케이스를 **Blocked** 로 기록하거나, 같은 버전 파일을 로컬로 대체해 실행하고 그 사실을 기록한다.

## 4. 진입·종료 기준

### 4.1 진입 기준

- `index.html` 이 문법 오류 없이 로드된다.
- `CLAUDE.md` 의 헤드리스 렌더 스크립트가 `clean` 을 출력한다 (TC-L-02). 실패하면 다른 케이스를 시작하지 않는다.
- 테스트 대상 커밋이 정해져 있고, `sw.js` 의 `CACHE` 값이 기록되어 있다.

### 4.2 종료 기준 (M0 프로토타입 기준)

- 실행 가능한 P0 케이스를 100% 실행했다 (Pass / Fail / Blocked 중 하나로 기록, 미실행은 사유 기재).
- **심각도 치명·높음 결함이 0건**이거나, 남은 건이 PRD 에 "프로토타입 한계"로 기록되어 다음 마일스톤으로 넘어갔다.
- 3개 언어 모두에서 JS 예외(pageerror) 0건.
- XSS 케이스(TC-SEC-01, 02) Pass.

### 4.3 종료 기준 (M1 백엔드 이후 추가)

- "백엔드 (M1 이후)" 로 표시된 PR-*, S-* 케이스가 모두 Pass. **하나라도 Fail 이면 M1 완료로 보지 않는다** (PRD §10 M1 완료 기준).

### 4.4 중단·재개 기준

- 앱이 첫 화면을 그리지 못하거나 JS 예외로 클릭 핸들러가 멈추면 중단하고 결함을 먼저 보고한다.
- 수정 후 TC-L-02 → 실패했던 케이스 → 같은 영역 회귀 순으로 재개한다.

## 5. 결과 판정과 심각도

| 결과 | 의미 |
|---|---|
| Pass | 기대결과 충족 |
| Fail | 기대결과 불충족 (미구현 포함 — 미구현은 리포트에서 결함과 구분해 표시) |
| Blocked | 환경(네트워크, 기기 부재 등) 때문에 실행 불가 |
| 미실행 | 이번 회차에 실행하지 않음 (백엔드 미구축 등). 사유 필수 |

| 심각도 | 기준 |
|---|---|
| 치명 | 익명성 붕괴, 권한 상승, 데이터 유출 |
| 높음 | 핵심 기능이 동작하지 않거나, 동작한 것처럼 보이지만 실제로는 안 됨 |
| 중간 | 기능은 되지만 데이터 손실·문맥 손실·잘못된 정보 노출이 있음 |
| 낮음 | 표시·문구·접근성·일관성 문제 |
