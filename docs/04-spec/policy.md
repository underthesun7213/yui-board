## POL-1 익명성

| # | 정책 | 상태 |
|---|---|---|
| 1-1 | 글·댓글에 이름, 방 번호, 층을 표시하지 않는다 | 확정 |
| 1-2 | 댓글 작성자는 글마다 독립된 번호로 표시한다. 글쓴이는 "글쓴이"(0번), 나머지는 처음 댓글을 단 순서대로 1, 2, 3… | 확정 |
| 1-3 | 글쓴이 정보는 운영자를 포함해 **어떤 클라이언트에서도** 조회할 수 없다. 서버 코드(`service_role`)만 접근한다 | 확정 |
| 1-4 | 서버 코드가 작성자 정보를 조회하는 경우는 법적 요청과 교환 요청 처리로 한정하고, 조회 기록을 남긴다 | 제안 |
| 1-5 | 모집 글은 실명·연락처를 공개하는 옵션을 둔다 | **충돌** — 문구만 있고 기능·스키마 없음 (PRD Q2) |

## POL-2 커뮤니티 규칙

글쓰기 화면에 그대로 표시되는 규칙 (확정):

1. **다른 사람**을 특정할 수 있는 내용 (이름, 방 번호, 층 + 인상착의)
2. 성적인 내용
3. 폭력적인 내용
4. 사람을 깎아내리거나 차별하는 내용

예외 (확정): 자기 글에 **자기** 연락처를 적는 것은 괜찮다. 모집 글에서는 흔한 일이다.

## POL-3 신고·운영

| # | 정책 | 상태 |
|---|---|---|
| 3-1 | 신고 사유 6종: 특정 가능 / 비방·괴롭힘 / 성적·불쾌 / 스팸·광고 / 사실과 다름 / 기타 | 확정 |
| 3-2 | 한 사람은 같은 대상을 한 번만 신고한다 | 확정 |
| 3-3 | 신고자는 글쓴이에게도, 운영자에게도 알려지지 않는다. 운영자는 대상·사유·건수만 본다 | 확정 |
| 3-4 | 운영자 조치는 "문제 없음 / 숨기기 / 복원" 세 가지. 삭제하지 않고 숨긴다 (되돌릴 수 있다) | 확정 |
| 3-5 | 모든 조치는 운영자 계정과 함께 기록되고, 기록은 수정·삭제할 수 없다 | 확정 (단, 현 스키마는 수정 가능 — PRD S-3) |
| 3-6 | 운영자는 익명이 아니다 | 확정 |
| 3-7 | **처리 목표 시간:** "특정 가능"·"성적" 사유는 12시간, 나머지 24시간 | 제안 |
| 3-8 | **자동 임시 숨김:** 서로 다른 입주자 5명이 신고하면 운영자 검토 전까지 자동 숨김 | 제안 |
| 3-9 | **이의 제기:** 숨김 처리된 글의 작성자는 한 번 이의를 제기할 수 있다. 처리한 운영자가 아닌 다른 운영자가 검토 | 제안 (PRD M-8) |
| 3-10 | 반복 위반자 제재(작성 정지 기간 등)는 작성자를 알아야 하므로 서버 코드에서만 처리하고, 운영자에게는 "제재 대상 여부"만 보인다 | 제안 |

## POL-4 프로필 교환

| # | 정책 | 상태 |
|---|---|---|
| 4-1 | 양도·모집·분실물 게시판 글에서만 요청할 수 있다 | 확정 (단, 스키마는 게시판을 확인하지 않음 — PRD Q7) |
| 4-2 | 요청자의 신원은 요청과 함께 상대에게 전달된다. 거절되어도 전달된다. 이 비대칭은 의도적이며 보내기 전에 경고한다 | 확정 |
| 4-3 | 전달되는 신원: 이름 + **방 번호 또는 층** | **충돌** — UI 는 방 번호, 스키마 뷰는 층 (PRD Q1) |
| 4-4 | 하루 3건까지 요청. 실패한 시도도 횟수에 포함 | 3건은 확정, 실패 포함은 제안 (PRD S-2) |
| 4-5 | 같은 상대에게 대기 중 요청은 1건, 이미 교환한 상대에게는 요청할 수 없다 | 확정 |
| 4-6 | 거절은 요청자에게 알리지 않는다. 수락되면 요청자의 교환 목록에 상대가 나타나는 것으로 알 수 있다 | 제안 (현재 UI 는 요청자에게 결과를 알려주는 화면이 없다) |
| 4-7 | 교환은 어느 쪽이든 해제할 수 있다. 해제하면 양쪽 목록에서 사라진다 | 확정 |
| 4-8 | 대기 중 요청은 14일 후 만료 | 제안 |

## POL-5 개인정보

| # | 정책 | 상태 |
|---|---|---|
| 5-1 | 방 번호는 저장하되 화면에 보이지 않는다. 화면에는 층만 | **충돌** (PRD Q1) |
| 5-2 | 다른 입주자의 프로필 테이블은 직접 조회할 수 없다. 교환한 상대만 뷰로 본다 | 확정 |
| 5-3 | `service_role` 키와 번역 API 키는 클라이언트와 저장소에 넣지 않는다 | 확정 |
| 5-4 | **퇴거 시:** 계정은 비활성화하고 입주 기록(`residency`)은 종료일을 남긴다. 글·댓글은 익명 상태로 남긴다(다음 입주자를 위한 기록이 이 제품의 목적). 본인이 요청하면 글·댓글 본문을 삭제한다 | 제안 (PRD PR-12) |
| 5-5 | 교환 목록은 퇴거 후 30일 뒤 삭제 | 제안 |
| 5-6 | 개인정보처리방침과 이용약관을 일본 개인정보보호법(APPI) 기준으로 작성하고, 가입 시 동의를 받는다 | 제안 |
| 5-7 | 지표 수집은 사용자 ID 없는 집계(일별 카운터)로만 한다 | 제안 (PRD Q10) |

## POL-6 번역

| # | 정책 | 상태 |
|---|---|---|
| 6-1 | 글·댓글은 **작성 시점에** 세 언어로 번역해 저장한다. 읽을 때 번역하지 않는다 | 확정 |
| 6-2 | 원문 언어를 저장하고, 다른 언어로 볼 때는 항상 "자동 번역" 표시와 원문 보기를 제공한다 | 확정 |
| 6-3 | 번역 실패 시 원문을 그대로 저장하고 `translated=false` 로 표시한다. 글쓰기는 막지 않는다 | 확정 |
| 6-4 | 무료 한도(월 200만 자)를 넘으면 그달은 번역 없이 원문만 저장한다 | 확정 |
| 6-5 | 이벤트·장소·학습 콘텐츠는 운영자가 직접 세 언어로 작성한다 | 제안 (스키마에 세 언어 칸이 있음) |
