# ADR-0017 · 장소·일정은 서버에 두고 모두가 공유한다 — ADR-0009(클라이언트 단독)의 공유 데이터 부분을 대체

| | |
|---|---|
| 상태 | 제안됨 |
| 날짜 | 2026-10-12 |
| 근거 | PRD-YUNABI v2.3 D16, D17, Y-M3, Y-M4, Y-K2, Y-C3, Y-R10, G2 |
| 관련 | [ADR-0009](0009-client-only-mlp.md) (**일부 대체**), [ADR-0011](0011-curated-static-data.md)(정적 데이터 — 사실상 대체), [ADR-0010](0010-device-storage-localstorage.md)(유지), ADR-0018, [RFC-0003 §11](../architecture/rfc/0003-yunabi-v2.md) |

## 배경

ADR-0009 는 MLP 를 "서버·DB·계정 없는 정적 PWA" 로 정하고 장소·일정을 사람이 `index.html` 에 넣어 배포하게 했다(ADR-0011). ADR-0009 의 재검토 조건은 "일정 갱신을 개발자가 아닌 사람이 맡아야 할 때" 였다. 책임자는 D16 으로 장소·일정을 **사용자 누구나 등록하고 모두에게 공유**하며 **초기 데이터 0** 으로 정했다. 이것은 서버 없이는 불가능하다.

## 결정

1. 장소·일정·회차 덮어쓰기는 **서버(Supabase, ADR-0018)에 저장**하고 앱은 공개 뷰에서 읽는다. v1.3 의 `PLACES`·`EVENTS` 상수와 샘플 13곳·6건은 운영 데이터로 옮기지 않고 테스트 고정 데이터(`tests/fixtures/`)가 된다(Y-M3, PRD §7).
2. ADR-0009 중 **대체되는 것:** 결정 1 의 "우리 쪽 서버·DB·계정·API 가 없다", 결정 2 의 "앱이 쓰는 데이터는 모두 같은 출처의 정적 파일", 결정 4(정적 데이터 + 재배포), 결과의 "운영비 0·우리 쪽으로 가는 데이터 0".
3. ADR-0009 중 **유지되는 것:** 결정 3(기억할 것은 기기에 — 컬렉션·언어·위치 선택, ADR-0010), 호스팅 GitHub Pages(ADR-0020 이 이어받음), 기기 간 동기화 없음, 게시판 계획 보류(v0.4 는 계속 비목표).
4. 읽기에는 계정이 필요 없다(`anon`). 오프라인에서는 마지막 스냅샷(IndexedDB)과 갱신 시각을 보여주고 쓰기를 막는다(Y-C3). 스냅샷은 응답으로 통째로 바꿔 숨김 항목이 남지 않게 한다(Y-R10).
5. ADR-0009 의 상태 줄을 "ADR-0017으로 일부 대체됨" 으로 바꾼다(본문은 고치지 않음).

## 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| 정적 데이터 유지 + 등록 요청을 폼으로 받아 책임자가 반영 | D16 "사용자가 등록하고 모두에게 공유" 와 다르다. 책임자 병목 |
| 공유 스프레드시트·캘린더 피드에서 읽기 (ADR-0009 대안) | 권한·검증·신고·자동 숨김을 할 수 없다(D18) |
| 기기 간 P2P | 범위·복잡도 과다 |

## 결과

- 좋은 점: D16·D17 을 만족. 갱신에 배포가 필요 없다.
- 나쁜 점: 서버 장애·한도·보안이 생긴다 — 그래서 D20 의 보안 기준선(ADR-0022). 개인정보 처리가 생겨 방침·약관이 필요하다(Y-P4). 운영비 0 은 "무료 한도 안" 으로 바뀐다.
- ADR-0011(정적 데이터)은 이 ADR 로 사실상 대체된다. 상태 줄 변경은 책임자 확인 후(RFC-0003 OQ-15) — 이번에는 지시받은 ADR-0009 만 바꿨다.
