## 배경

`schema.sql` 은 두 방식을 동시에 암시한다: 방 계정(`<room>@yui.local`, 방 주인이 바뀌면 auth 행 이름만 변경)과 허용 도메인 테이블(`allowed_domains`). 가입 시 `profiles`·`residency` 를 만드는 경로가 없다(S-7).

이 ADR 작성 중 확인한 문제:
- **방 계정 모델은 uuid 를 방에 묶는다.** 다음 입주자가 이전 입주자의 작성 이력(`post_authors`), 교환 목록(`my_contacts`)을 물려받는다. M-7(본인 글 수정·삭제)이 들어오면 남의 글을 고칠 수 있다. 사람별 이력인 `residency` 와도 모순이다.
- **학교 이메일만으로는 "현 입주자"(POL-9-1)를 증명할 수 없다.** 학생이지만 입주자가 아닐 수 있다.
- **매직 링크는 설치형 PWA 에서 문제가 된다.** iOS 에서 링크가 Safari 로 열려 설치된 앱은 로그인되지 않는다(실기기 확인 필요).

## 결정

1. **신원 = 이메일 OTP(6자리 코드).** Supabase Auth 이메일 OTP, 앱 안에서 코드 입력. 비밀번호 없음.
2. **가입 허용 = 이메일 도메인 허용 목록.** `before-user-created` 훅(Postgres 함수)이 `allowed_domains` 를 조회해 거부한다. 신규 `auth.users` 행이 생기면 트리거가 `profiles` 를 만든다.
3. **입주 확인 = 방 초대 코드.** 사무실이 방마다 1회용 코드(만료 30일 *제안*)를 발급해 입주 안내물과 함께 전달한다. 사용자가 `claim_residency(code)` 로 입력하면 `residency` 행이 생긴다. 코드는 해시로 저장한다.
4. **uuid 는 사람에게 묶는다.** 퇴거·방 이동은 `residency.active=false, ended_on` 으로 처리하고 새 코드를 발급한다. 작성 이력·교환은 사람을 따라간다.
5. **외부 SMTP 를 쓴다.** Supabase 기본 발송은 시간당 몇 통 수준이다(tech-stack §4.3).

## 고려한 대안

| 대안 | 장점 | 기각 이유 |
|---|---|---|
| 방 계정 `<room>@yui.local` + 비밀번호 (사무실 발급) | 이메일 불필요, 입주 확인이 계정 발급과 같음 | 작성 이력·교환 승계(PR-8 위반), 비밀번호 배포·재설정을 사무실이 해야 함 |
| 방 계정을 사람마다 새로 발급 (방 이름 + 학기) | 승계 문제 없음 | 비밀번호 배포·재설정 부담 그대로, 이메일 없이 복구 경로 없음 |
| 학교 이메일만 (도메인 = 입주 확인) | 운영 부담 최소 | 비입주 학생 가입 가능 → POL-9-1 위반 |
| Google/Microsoft OAuth | 비밀번호·메일 발송 불필요 | 학교 계정이 어느 쪽인지 미확인. 교환학생의 본교 계정 도메인이 제각각 |
| 매직 링크 | 구현 간단 | 설치형 PWA 저장소 분리 문제 |

## 결과

- 좋은 점: 신원과 입주를 분리해 학기 전환이 `residency` 갱신만으로 끝난다. uuid 승계 문제가 없다.
- 나쁜 점: 사무실이 학기마다 초대 코드를 출력·배포해야 한다(약 650개). 사용자는 첫 실행에 이메일 코드와 방 코드 두 번 입력한다.
- 이 ADR 이 승인되면 `schema.sql:21-26` 의 방 계정 주석과 PRD §9 의 인증 문단을 고쳐야 한다.

## 열린 질문

| # | 질문 |
|---|---|
| L-Q1 | 교환학생이 입주 시점에 간사이외대 이메일을 갖는가. 없다면 본교 도메인을 `allowed_domains` 에 계속 추가해야 한다(테이블로 둔 이유와 일치) — RFC R-2 |
| L-Q2 | 사무실이 학기마다 초대 코드(약 650개)를 발급·배포할 수 있는가 (BL-10 사무실 승인과 함께) |
| L-Q3 | 무료 SMTP 제공자와 그 발송 한도 (tech-stack T-2) |
| L-Q4 | iOS 설치형 PWA 의 저장소 분리(매직 링크 문제)를 실기기 ENV-1 로 확인 |
| L-Q5 | 초대 코드 분실·오입력 시 재발급 절차와, 코드 입력 시도 횟수 제한(무차별 대입 방지)을 둘 것인가 |
