# ADR-0009 · MLP 는 서버 없는 클라이언트 단독 PWA 로 내고, 백엔드 계획은 보류한다

| | |
|---|---|
| 상태 | 제안됨 |
| 날짜 | 2026-10-12 |
| 근거 | PRD-MLP v1.3 §1~§3 (D1~D11 — 특히 D1, D2, D9, G1~G6), ML-P1, ML-K8, Q-M9 |
| 관련 | [RFC-0002](../architecture/rfc/0002-mlp-client-only.md), [RFC-0001](../architecture/rfc/0001-m1-backend-foundation.md)(보류), ADR-0010~0014 |

## 배경

PRD v0.4 의 첫 출시(M1~M5)는 로그인, 익명성을 DB 구조로 강제하는 백엔드(Supabase), 운영자 기능, 번역 서버가 모두 있어야 했다. 책임자는 2026-10-12 게시판을 빼고(D1) 서버 없이 지금 쓸 수 있는 세 기능만 내기로 했다(D2, G5 "서버·DB·계정 없음, 운영비 0"). 남은 기능 중 서버가 필요해 보이던 것은 두 가지였다.

- 엔딩 컬렉션 기록 (D3) — 기기에 저장으로 해결 (ADR-0010)
- 일정 참가 인원 — 집계하지 않음(PRD §3 비목표), 참가 버튼 자체를 제거(Q-M9 답)

## 결정

1. MLP 는 **정적 파일만으로 동작하는 PWA** 다. 우리 쪽 서버·DB·계정·API 가 없다. 호스팅은 GitHub Pages(ADR-0008 결정 1 유지).
2. 런타임 외부 요청은 OSM 타일과 사용자가 누른 Google 지도 링크뿐이다(ML-P4). 앱이 쓰는 데이터는 모두 같은 출처의 정적 파일이다.
3. 기억할 것은 기기 저장소에만 둔다(ADR-0010). 기기 간 동기화는 하지 않는다.
4. 장소·일정은 직접 넣은 정적 데이터다(ADR-0011). 갱신 = 데이터 수정 + 재배포.
5. **백엔드 계획은 보류한다**(삭제하지 않음). 상태를 "보류 (ADR-0009)" 로 바꾸는 ADR:

| [0004](0004-login-method.md) | 로그인 방식 | 보류 |
| [0005](0005-exchange-request-redesign.md) | 교환 요청 | 보류 |

| [0007](0007-anonymous-metrics.md) | 익명 지표 | 보류 — MLP 는 앱 안 지표 없음(ML-P6) |

## 고려한 대안

| 대안 | 장점 | 단점 / 기각 이유 |
|---|---|---|
| RFC-0001 대로 M1 백엔드부터 | 게시판으로 가는 길이 이어진다 | 첫 출시가 로그인·익명성·운영 정책 결정을 모두 기다린다. D1 과 충돌 |
| 최소 백엔드 — 익명 인증 + 컬렉션 동기화·참가 집계 | 기기 변경에도 컬렉션 유지, 참가 인원 | 계정·개인정보 처리·운영비가 생긴다(G5 위반). 650명 규모에서 참가 집계 가치가 낮고 Q-M9 로 버튼이 제거됨 |
| 일정만 외부 서비스(공유 스프레드시트, 공개 캘린더 피드)에서 읽기 | 담당자가 배포 없이 갱신 | 외부 요청·제3자 의존이 늘고 오프라인·헤드리스 검사가 복잡해진다. 갱신 담당도 아직 없다(Q-M11) — 담당이 정해지면 다시 볼 대안 |

## 결과

- 좋은 점: 운영비 0, 개인정보 처리 최소(우리 쪽으로 가는 데이터 0), 장애 지점은 GitHub Pages 와 OSM 타일뿐. 배포는 push 한 번.
- 나쁜 점: 기기를 바꾸거나 저장소가 지워지면 컬렉션이 사라진다. 일정·장소를 바꾸려면 저장소에 커밋할 수 있는 사람이 필요하다. 사용 지표가 없다(PRD §10 은 시연으로 판단).
- 재검토 조건: 게시판(v0.4)을 다시 시작할 때, 또는 일정 갱신을 개발자가 아닌 사람이 맡아야 할 때. 그때 새 ADR 로 이 ADR 을 대체하고 보류한 ADR 을 다시 검토한다.
