## 배경

익명 계정은 만들기 쉬워 신고 남용(여러 계정으로 정상 항목 숨기기)이 가능하다. 처음 초안은 신고자 자격(계정 나이 24시간, 신고 실적), 전역 자동 숨김 차단기를 두었으나, 책임자가 **D20**(예상 약 600명 — 사용자 악용 대응은 단순하게, 외부 공격 보안에 집중)으로 정했다: Y-R3 = 서로 다른 계정 3개, 자격 조건·CAPTCHA 같은 추가 장치 없음, 관리자 복원과 복원 후 재숨김 방지(Y-R6)로 충분.

## 결정

1. **자동 숨김:** 한 항목에 대한 **미처리 신고의 서로 다른 신고자 수 ≥ N**(기본 3, `app.settings`)이면 신고 트랜잭션 안에서 숨긴다. 대상 행을 `for update` 로 잠가 동시 신고에도 한 번만. 신고자 자격 조건·평판·CAPTCHA 는 두지 않는다(D20).
2. **신고:** 사유 5개(Y-R1), 한 계정 한 항목 한 번(Y-R2), 계정당 24시간 20건(Y-A3), 정지 계정 불가(Y-R7). 일정은 시리즈 단위. 등록자 자신의 신고는 저장하되 세지 않는다(`by_owner` 는 INSERT 전에 계산). **정지된 계정의 미처리 신고도 세지 않는다**. 자유 서술 없음. `[보안 검토 낮음·nit 반영]`
3. **보호(Y-R6):** 관리자가 복원하면 `restored_at` 을 남기고 그 항목은 자동 숨김 대상에서 빠진다. 신고는 계속 쌓여 관리자 화면에 보인다. **등록자가 수정하면 보호가 풀리고**, 그 시점의 미처리 신고로 즉시 다시 평가한다(v2.3).
4. **수정·삭제(Y-E1~E3):** 수정은 신고를 지우지 않고 숨김을 풀지 않는다. 등록자는 숨김 항목도 삭제할 수 있다. 삭제는 30일 보관 후 영구 삭제.
5. **관리자 조치:** 복원, 삭제, 신고 기각(보이는 항목), 계정 정지·해제. 정지하면 그 계정은 쓰기·신고 불가, 보이는 항목은 모두 숨김. **해제해도 항목은 숨김 유지** — 관리자가 항목별로 복원(Y-R7 v2.3).
6. **보이는 것:** 관리자에게 사유별 건수·첫/마지막 신고 시각·등록자 가명 ID. 신고자는 누구에게도 보이지 않는다(Y-R9). 등록자에게는 ME-02 에서 "신고로 숨겨짐 — 검토 중"(원인 구별 없음, Y-R8). 신고자에게 숨김 여부를 알려 주지 않는다.
7. **감사 기록(ADR-0006 재사용):** `app.mod_actions` 추가 전용(행 트리거 + TRUNCATE 문장 트리거, **security invoker**). 자동 숨김은 `actor_kind='system'`, 관리 조치는 관리자 id·이메일 스냅샷. 본문 사본은 남기지 않는다. 1년 지난 행만 정리 함수가 지운다(Y-P5).
8. **스크립트 대량 숨김(Y-A4 의 자동화 공격)은 막는 대신 알리고 런북으로 되돌린다** `[보안 검토 #10]`. 규모: 전역 가입 한도(시간당 200 계정)로 신고 3건씩이면 **시간당 약 1,300건**을 숨길 수 있다(*추정*). D20 에 따라 전역 차단기는 두지 않고, ① 감시가 1시간 자동 숨김 5건 초과를 경보(ADR-0022) → ② 관리자가 CAPTCHA 스위치 ON(새 계정 생성 차단) → ③ `admin_restore_bulk(기간)` 로 그 기간의 자동 숨김을 일괄 복원(미리보기 기본, 항목마다 기록) → ④ 남은 신고 기각. 복원된 항목은 결정 3 으로 보호된다. 런북은 RFC-0003 §17.7 R-1. **이 수동 복원 비용을 받아들일지는 책임자 결정**(MO-Q4).

## 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| 신고자 자격(계정 나이 24시간, 쓰기 실적) | 첫 초안. D20 으로 제외. 게다가 Y-A1(첫 쓰기 때 계정 생성) 아래서는 첫 신고가 곧 계정 생성이라 정상 사용자의 첫 신고가 24시간 동안 세지지 않는 부작용이 있었다 |
| 신고 실적(복원된 신고에 벌점) | D20 으로 제외. 관리자 정지로 대신 |
| 전역 차단기(24시간 자동 숨김 N건 초과 시 중단) | D20 으로 제외. 감지·알림(결정 8)으로 대신 |
| 신고만 받고 숨김은 관리자 수동 | G3 "신고만으로 빨리 사라진다" 위반 |
| 사유별 다른 N (개인정보 노출은 2) | 단순성. 필요하면 설정값을 사유별로 늘리는 마이그레이션 |

## 결과

- 좋은 점: 규칙이 짧고 테스트하기 쉽다(ERD v2 §9 G-24~G-28). 남용으로 숨겨진 항목은 관리자 복원 한 번으로 영구히 보호된다(수정 전까지).
- 나쁜 점: 한 사람이 계정 3개로 정상 항목을 숨길 수 있다 — 관리자가 복원할 때까지. 600명 규모에서 받아들인 위험(D20). 관리자가 오래 비면 숨김이 유지된다 → 감시가 "미처리 신고 24시간 초과" 를 알림.
