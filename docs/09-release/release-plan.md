**알려진 문제:** [QA 리포트](../08-qa/qa-report.md) 의 결함 목록 참조.

## 3. 지표 대시보드 정의

PRD §11 의 목표를 측정 가능한 정의로 바꾼다. **익명성 원칙(POL-5-7):** 모든 지표는 사용자 ID 없이 일별 집계로만 남긴다.

| 지표 | 정의 | 데이터 소스 | 목표 | 주기 |
|---|---|---|---|---|
| 주간 활성 입주자 | 7일 안에 앱을 1회 이상 연 입주자 수 ÷ 활성 입주 수 | ✚ 익명 카운터 `weekly_opens(week, n)`: 기기가 그 주에 처음 앱을 열 때 1 증가 (주 단위 중복 방지는 기기 localStorage 플래그). 사용자 ID 를 저장하지 않는다(POL-5-7). 기기 기준이라 한 사람이 기기 2대를 쓰면 2로 센다 — 근사치. `auth.users.last_sign_in_at` 은 로그인할 때만 바뀌어 쓰지 않는다 | 30% | 주 |
| 주간 신규 글 | 7일간 `posts` 생성 수 (게시판별) | `posts.created_at` | 30건 | 주 |
| 주간 신규 댓글 | 7일간 `comments` 생성 수 | `comments.created_at` | — (관찰) | 주 |
| 비원어 열람 비율 | 글 상세 조회 중 조회 언어 ≠ 원문 언어 비율 | ✚ 일별 카운터 테이블 `daily_views(day, src_lang, view_lang, n)` (PRD Q10) | 40% | 주 |
| 원문 보기 사용률 | 비원어 조회 중 "원문 보기"를 누른 비율 (번역 품질 신호) | ✚ 같은 카운터 | 관찰 | 주 |
| 번역 실패율 | `translated=false` 비율 | `posts`, `comments` | 1% 미만 | 일 |
| 번역 사용량 | 월 누적 번역 글자 수 ÷ 200만 | 서버 로그 | 80% 도달 시 경고 | 일 |
| 신고 처리 시간 | 신고 생성 → `resolved_at` 중앙값, 사유별 | `reports` (집계만) | 24시간 (특정 가능·성적 12시간) | 주 |
| 숨김 비율 | 숨긴 글 ÷ 전체 글 | `posts.hidden_at` | 2% 미만 | 월 |
| 교환 성사율 | 수락 ÷ 요청 | `exchange_requests.status` | 관찰 | 월 |
| 이벤트 참가 | 이벤트별 RSVP 수 | `event_rsvps` | 관찰 | 주 |
| 일본어 완독 | 에피소드별 끝까지 본 수 | ✚ 일별 카운터 | 관찰 | 월 |
| 학기 전환 잔존 | 새 입주자 중 입주 4주 내 가입 비율 | `residency.started_on`, `profiles.created_at` | 50% | 학기 |

**대시보드 구현:** Supabase SQL 뷰 + 주 1회 운영자에게 요약. 별도 분석 도구(GA 등)는 쓰지 않는다 — 익명성과 비용 원칙.

**경보:** 신고가 24시간 넘게 미처리이면 운영자 전원에게 알림. 번역 사용량 80%.

## 4. 운영 체계

| 역할 | 담당 | 할 일 |
|---|---|---|
| 운영자 | RA (여러 명) | 신고 큐 처리, 유닛 이벤트 등록 |
| 관리자 | 사무실 담당 + 개발자 1 | 운영자 권한 부여·회수, 공식 이벤트·장소 등록 |
| 개발 | 개발자 | 배포, 장애 대응, 백로그 |

**학기 전환 체크리스트**
1. 퇴거자 `residency` 종료, 계정 비활성 (POL-5-4)
2. 교환 목록 30일 후 삭제 (POL-5-5)
3. RA 교대 시 운영자 권한 회수·부여
4. 새 학기 GIP 반복 이벤트 등록
5. 장소 정보 점검 (폐업 등)
6. 지표 회고 → 백로그 갱신
