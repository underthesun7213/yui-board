## Y-BL-02 메모 — 구글 지도 링크 → 핀

- **긴 링크**(`google.com/maps/place/…/@34.81,135.65,17z/data=…!3d34.8123!4d135.6543`): 좌표가 링크 안에 있다. `!3d…!4d…`(장소 좌표)를 먼저, 없으면 `@위도,경도`(그때 화면 중심 — 덜 정확)를 읽는다. **앱 안에서, 비용·서버 없이** 가능 — `src/domain/links.ts` 옆의 순수 함수.
- **짧은 링크**(`maps.app.goo.gl/…`, 휴대폰 앱의 "공유" — 실제로 더 흔할 것): 좌표가 없고, 열어 봐야 긴 링크로 바뀐다. 브라우저는 CORS 때문에 직접 따라갈 수 없다 → 짧은 링크를 따라가 바뀐 주소만 돌려주는 작은 Cloudflare Worker 가 필요하다. **"서버 없음" 설계에 처음 서버 코드가 생기는 결정**이라 따로 계획·검사: `maps.app.goo.gl` 만 받기(아무 주소나 대신 여는 통로 금지), 앱 CSP `connect-src` 갱신, 남용 한도.
- 구글 Places·Geocoding API(유료, 키·결제 계정)는 필요 없다.
- 화면: 좌표를 찾으면 바로 옮기지 않고 "이 위치로 핀을 옮길까요?" 로 미리 보여 주고 확인받는다. 서버의 위치 규칙(`app.pref_of` — 일본 범위, 가장 가까운 현 10km 안)은 그대로 마지막 검사다.
- 순서 제안: 1단계(긴 링크)는 작고 안전해 먼저, 2단계(짧은 링크)는 e2e 점검에서 기숙사생이 실제로 어떤 링크를 붙여 넣는지 본 뒤 정한다.
