## 1. 무엇이 바뀌나

1. **장소와 일정은 사용자가 등록해 모두가 함께 본다.** 초기 데이터는 0. 서버가 다시 필요하다.
2. **이름은 YUNABI**, 로고는 연파랑 나비.
3. **Vite + TypeScript + 프레임워크로 다시 만든다.** 과제용으로 두었던 제약은 없앤다.

## 3. 목표 / 비목표

### 목표

- G1. 로그인 화면 없이 바로 쓰고, 바로 등록한다 (D17)
- G2. 한 사람이 등록한 장소·일정을 모두가 본다 (D16)
- G3. 잘못된 등록은 신고만으로 빨리 사라지고, 관리자가 최종 판단한다 (D18)
- G4. 일본어 만화·게임·컬렉션은 v1.3 그대로 (컬렉션은 기기에 저장)
- G5. 일반적인 구조로 유지보수할 수 있다 (D19)

### 6.1 보안 (외부 공격 대비, D20)

공개 웹 앱이고 익명 쓰기가 열려 있으므로, 사용자 규모와 관계없이 아래를 지킨다. 각 항목의 구체적 방법은 설계에서 정하고, 수락 기준은 자동 테스트나 점검표로 확인한다.

| ID | 요구사항 | 수락 기준 |
|---|---|---|
| Y-S1 | **권한은 서버에서만 판단한다.** 화면이 숨긴 기능이라도 서버가 막아야 한다: 남의 항목 수정·삭제, 숨김 항목 읽기, 관리자 기능, 신고자 조회 | 권한 테스트(클라이언트를 거치지 않는 직접 요청)가 전부 거절 |
| Y-S2 | **비밀 키는 클라이언트·저장소에 없다.** 공개 키만 클라이언트에. 저장소와 빌드 결과물에 비밀 키가 들어가면 CI 가 실패 | CI 비밀 검사 통과, 빌드 결과물 검사 |
| Y-S3 | **관리자 계정 보호:** 별도 로그인 + 2단계 인증, 허용 목록, 세션 만료, 관리자 조치 기록 | 2단계 인증 없이는 관리자 화면 진입 불가 |
| Y-S4 | **XSS 방지:** 사용자 글은 항상 텍스트로 출력(HTML 해석 금지), 링크는 허용 도메인만, 콘텐츠 보안 정책(CSP)으로 외부 스크립트 차단 | 사용자 글에 넣은 스크립트가 실행되지 않음(E2E), CSP 위반 0 |
| Y-S5 | **입력 검증과 주입 방지:** 모든 입력을 서버에서 형식·길이 검사, 데이터베이스 쿼리는 문자열 조합 없이 | 비정상 입력 테스트 세트가 전부 거절 |
| Y-S6 | **의존성 보안:** 잠금 파일, 알려진 취약점 자동 검사(CI), 자동 업데이트 알림 | 높음 이상 취약점이 있으면 CI 실패 |
| Y-S7 | **자동화 공격 대비:** 익명 계정 생성·쓰기·신고에 IP·계정 단위 빈도 제한, 대량 요청 차단. 공격이 확인되면 켤 수 있는 사람 확인(CAPTCHA) 스위치 | 빈도 초과 요청 거절, 스위치 동작 확인 |
| Y-S8 | **전송 보안:** HTTPS 만, 혼합 콘텐츠 없음 | 점검표 |
| Y-S9 | **백업과 복구:** 정기 백업, 복구 절차를 문서로 두고 출시 전 한 번 복구해 본다 | 복구 리허설 기록 |
| Y-S10 | **감시:** 관리자 조치, 권한 거절 급증, 빈도 제한 초과 급증을 기록하고 관리자에게 알림 | 알림 시험 |
| Y-S11 | **출시 전 보안 점검:** 권한 테스트, 자동 취약점 스캔, 위 항목 점검표 | 점검 기록 |
| Y-S12 | **데이터 최소화:** Y-P1 이외의 정보를 모으지 않는다 (공격당했을 때 잃을 것을 줄임) | 스키마 검토 |
