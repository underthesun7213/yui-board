## 무엇인가

오사카 신세카이의 쿠시카츠 가게에 유우키와 간다. 테이블에 마주 앉아 스마트폰 모바일 오더로 주문하고, 소스를 한 번만 찍어 먹고(二度漬け禁止), 계산하고 나온다. 6단계:

1. **飲み物** — 유우키 「とりあえず飲み物決めよか。何にする？」. 친구에게 하는 대답 고르기 (「とりあえず生で！」○, 「ウーロン茶にしようかな。」○, 「生ビールをいただけますでしょうか。」× 너무 정중함)
2. **モバイルオーダー** — 휴대폰 주문 화면에서 꼬치 4종류 이상, 음료 포함 2,000엔 이하. 화면 말(数量·カート·合計·注文を確定する) 읽기
3. **数え方** — 유우키에게 「牛かつを2＿頼んだよ。」: 本 / 個 / 枚. 本의 소리 변화(いっぽん·にほん·さんぼん)
4. **食べる** — 꼬치를 소스 통으로 끌어 찍고, 두 번 톡톡 눌러 한 입. 한 입 먹은 꼬치를 다시 찍으면 유우키가 웃으며 「二度漬けはアカンで〜」(그림이 바뀌고 음성만, 얼굴을 가리는 글자는 없음)
5. **お会計** — 계산대에서 「すみません、お会計お願いします。」(おあいそ·お金を払いたいです 는 ×), 금액을 가나로 읽기
6. **退店** — 「ごちそうさまでした！」, 점원 「おおきに！」

## 정한 것 (책임자, 2026-10-29)

- 점수·하트·별점이 없다. 맞으면 ○ 와 설명, 틀리면 × 와 설명 후 다시 고른다 (YUNABI 안의 시뮬레이션 게임으로 들어가므로)
- 사장님(점원)은 그림에 나오지 않는다. 주문은 모바일 오더, 점원은 대사로만
- 양배추로 소스를 뜨는 기능은 없다
- 그림은 만화와 같은 화풍, 화면은 앱의 "Clear Sky" 색(`src/styles/tokens.css`)
- 설명 문구는 지금 영어. 대사는 일본어 + 후리가나

## 앱에 넣을 때 할 일

이 파일은 독립 HTML 이라 앱의 규칙과 다른 곳이 있다. 넣을 때:

- **문구 3개 언어:** 설명·선택지 뜻·안내를 `src/i18n` 처럼 ja·en·ko 로. 대사는 `{漢字|かな}` 후리가나 표기 그대로 쓸 수 있다 (D34)
- **글은 텍스트로만:** 지금은 `esc()` 한 문자열을 `innerHTML` 로 넣는다. 앱에서는 JSX 로 (CLAUDE.md, ESLint)
- **음성:** 지금은 브라우저 음성(speechSynthesis). 만화처럼 Azure 음성 파일로 만든다 (D35). 대사를 `src/content/voice-lines.ts` 에 넣고 책임자가 `node scripts/gen-voice.mjs` 를 돌린다 (런북 §7.5, 키는 책임자 PC 에만). 목소리는 이미 있는 배역을 쓴다 — 유우키 `ja-JP-NaokiNeural`(레벨 8 오사카 루트와 같은 목소리), 점원 `ja-JP-KeitaNeural`, 플레이어 대사 `ja-JP-DaichiNeural`/`ja-JP-ShioriNeural`. **고정 녹음이 안 되는 대사 2개:** 주문 확인(「ええやん！牛かつ2本、…な。」 — 주문마다 다름)과 금액(「全部で1,300円です。」). 문장을 고정하거나(「ええやん！ええ感じやな。」 처럼), 숫자는 녹음 없이 글자로만 보인다
- **음성 시점:** 레벨 8 과 같이 시나리오 문서에서 이 게임이 들어갈 자리와 대사가 정해진 뒤에 녹음한다 (바뀌면 다시 녹음해야 하므로)
- **애니메이션:** 지금은 GSAP(CDN). 앱 번들 예산(학습 30 KB)을 생각해 CSS 애니메이션으로 바꾸거나 크기를 확인한다
- **그림:** `src/art/` 아래로 옮기고 규격·크기 확인 (장면 4:3, 한 장 400 KB 이하)
- **화면 추가 절차:** `features/` 컴포넌트, 경로, `app/screens.ts`, `App.tsx`, 렌더 검사 (CLAUDE.md "To add a screen")
- **시험:** 렌더 검사 상태, e2e (주문 → 먹기 → 두 번 찍기 → 끝)
